# Лендинг FidRid

Статический сайт на двух языках, публикуется через GitHub Pages:
**https://svalia.github.io/fidrid-landing/**

Приложение живёт в отдельном репозитории: [svalia/FidRid](https://github.com/svalia/FidRid).

## Что где лежит

| Путь | Что это |
| --- | --- |
| `index.html` | Главная страница, стили инлайновые (так её отдал макет) |
| `i18n.js` | Двуязычность главной: словарь и выбор языка |
| `responsive.css` | Адаптив, дописан поверх макета |
| `css/` | Дизайн-система: токены, базовые стили, шрифт Golos Text |
| `assets/` | Логотип, QR-код, фавиконы, OG-превью |
| `legal/` | Юридические документы: HTML-страницы, PDF и markdown-исходники |
| `source/` | Исходный артефакт дизайна, из которого собрана главная |
| `tools/` | Скрипты сборки |

## Адреса для App Store Connect

| Поле | Адрес |
| --- | --- |
| Privacy Policy URL | `https://svalia.github.io/fidrid-landing/legal/privacy/` |

Страницы отдают язык по локали устройства, так что ревьюер из Apple увидит английскую версию.
Support URL требует способа связаться: в футере главной ссылка «Поддержка» ведёт на почту.

## Языки

Страница открывается на русском или английском без участия пользователя:

1. если человек раньше переключал язык вручную, берётся его выбор из `localStorage`;
2. иначе смотрим `navigator.language`: русский язык системы - русская версия, любой другой - английская;
3. переключатель в шапке меняет язык и запоминает выбор.

Ключ в `localStorage` общий у главной и страниц документов, поэтому выбор языка переносится
между ними.

На главной русский текст лежит прямо в разметке, английский - в словаре `DICT` внутри
`i18n.js`: скрипт обходит текстовые узлы и подменяет совпадения. Заодно меняются `<title>`,
описание, OG-теги и `alt` у картинок. Чтобы страница не мигала русским перед показом
английского, язык определяется коротким скриптом в `<head>` ещё до отрисовки.

На страницах документов подход другой: обе версии текста лежат в разметке целиком, а
`legal/legal.js` показывает нужную и подставляет к ней свой PDF.

## Юридические документы

Каждый документ существует в трёх видах: markdown-исходник, PDF и страница на сайте.

| Документ | Страница | Исходник |
| --- | --- | --- |
| Условия использования | `legal/terms/` | `legal/_sources/Terms_of_Use_{Ru,En}.md` |
| Политика конфиденциальности | `legal/privacy/` | `legal/_sources/Privacy_Policy_{Ru,En}.md` |
| Обработка персональных данных | `legal/consent/` | `legal/_sources/Consent_to_Personal_Data_Processing_{Ru,En}.md` |

PDF лежат рядом в `legal/` под теми же именами и предлагаются кнопкой внизу страницы.

Чтобы обновить документ: правится markdown, заново собирается PDF, оба файла кладутся под
прежними именами, после чего пересобираются страницы:

```bash
python3 tools/legal.py
```

Имена файлов и состав документов заданы в словаре `DOCUMENTS` в начале `tools/legal.py`.
Почта поддержки - там же, в `SUPPORT_EMAIL`, и в `tools/assemble.py`.

## Пересборка главной из макета

Главная собрана из артефакта Claude Design (`source/FidRid Landing.dc.html`). Сам по себе он
не статический: в браузере подгружает React и Babel с CDN и рисует разметку на лету. Для
лендинга это лишний вес и пустая страница для поисковиков, поэтому она «запечена».

Если дизайн обновится, кладём новый экспорт в `source/` и повторяем:

```bash
node tools/bake.mjs "file://$PWD/source/FidRid Landing.dc.html" build/baked-raw.html
python3 tools/assemble.py
```

`bake.mjs` открывает макет в headless Chrome, дожидается отрисовки и снимает готовый DOM.
Попутно чинит две вещи, которые теряются при обычной сериализации: CSS-правила, вложенные
рантаймом через CSSOM (это hover-состояния), и градиентную заливку текста.

`assemble.py` собирает из этого `index.html`, `i18n.js` и `responsive.css`: переносит стили,
добавляет мета-теги и подключает документы.
